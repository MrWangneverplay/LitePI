## 六、2026-10-26 本地复现检查（不依赖远程 / GPU）

在 WSL 的 `/usr/bin/python3`（3.10.11，torch 可用）下跑了一遍仓库里现成的守门脚本：

| 检查 | 命令 | 结果 |
|---|---|---|
| canonical 三网络几何 | `check_canonical_contract.py` | PASS ×3（256/1200/756 → 64/128/128 → 10/10/6，槽位 4096/3200/2016） |
| 协议模式与轮数 | `check_protocol_modes.py` | PASS：s=(0,)→2 轮；s=(1,)→3 轮；s=(0,1)→3 轮；dummy 轮可掩盖混合调度 |
| 合规门禁 | `check_protocol_compliance.py` | 仅 `python_runtime` FAIL（要求 3.11，实际 3.10）；其余 11 项 PASS |
| 三数据集端到端数学一致性 | `eval_encrypted.py --backend stub --samples 3` | MNIST/CIFAR/UCI 全部 `err ≈ 1.8e-15`（浮点零） |

stub 检查的意义：它把「im2col 打包 → conv → pack → P₂ 移位折叠 → fc1 → P₂ → fc2」整条链路
用明文实现跑一遍，与 `plain_forward_prepared` 逐元素比对。误差 1e-15 说明**密文路径与明文
参考的代数结构完全一致**，剩下的差异只可能来自 SEAL 的缩放/噪声，不是代码写错了。

`python_runtime` 这一项 FAIL 是环境口径问题，不是协议问题：SEAL 4.1.2 的 `.so` 是针对
3.10 编的，而实验方案 §2.2 写的是 3.11。二选一（明天定）：把方案里的版本改成 3.10，
或在容器里补一个 3.11 并重编 `.so`。在改之前，论文实现表不能写 3.11。
