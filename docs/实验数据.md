## E1 · CIFAR-10 深度卷积（RGB + BN）

| 配置 | 卷积层数 | 通道/隐藏 | epoch | 种子 | 明文精度 | 乘法深度 | 6 层预算 | 路线 |
|---|---|---|---|---|---|---|---|---|
| relu + RGB + BN | 2 | 64 / 256 | 50 | 73-75 | **80.79 ± 0.19%** | 6 | 装得下 | hybrid（ReLU 走 MPC） |
| p2 + RGB + BN | 2 | 64 / 256 | 50 | 73-75 | 78.57 ± 0.08% | 6 | 装得下 | HE-only 基线 |
| relu + RGB + BN | 3 | 64 / 256 | 50 | 73-75 | **85.10 ± 0.48%** | 8 | 超出 | hybrid |
| p2 + RGB + BN | 3 | 64 / 256 | 50 | 73-75 | 78.76 ± 1.03% | 8 | 超出 | 同深度对照（HE-only 不可部署） |
| relu + RGB + BN | 4 | 64 / 256 | 50 | 73-75 | **88.55 ± 0.36%** | 10 | 超出 | hybrid |
| p2 + RGB + BN | 4 | 64 / 256 | 50 | 73-75 | 80.50 ± 0.80% | 10 | 超出 | 同深度对照（HE-only 不可部署） |

说明：

- 这是明文 PyTorch 训练精度；hybrid 模式下 MPC ReLU 是精确的，所以它是 hybrid 的精度上限（密文端还需单独验证 CKKS 线性层精度）。
- 全部在 Kaggle T4 上完成；per-seed JSON 已下载到 `litepi_results/`，均值/标准差由 seed73-75 计算。
- 2 卷积的乘法深度 6，P2 可以 HE-only 部署；3/4 卷积深度 8/10，超过预算，P2 不可 HE-only 部署，只有 hybrid ReLU 能跑。
- 这是论文 §4.2 性质 2 的直接实证：深网的精度必须靠 hybrid 换深度。

## ReLU vs P2（同深度对照）

| 深度 | ReLU | P2 | ReLU − P2 |
|---|---|---|---|
| conv2（depth 6） | 80.79 ± 0.19% | 78.57 ± 0.08% | **+2.22** |
| conv3（depth 8） | 85.10 ± 0.48% | 78.76 ± 1.03% | **+6.34** |
| conv4（depth 10） | 88.55 ± 0.36% | 80.50 ± 0.80% | **+8.05** |

三条结论：

1. 可部署的 HE-only 基线（conv2 + P2，depth 6）是 78.57%；hybrid conv4 达到 88.55%，高 **9.98 个点**。
2. ReLU 相对 P2 的优势随深度扩大：2.22 → 6.34 → 8.05，和 FC 深度实验的趋势一致（depth 2/3/4 差 0.22/2.04/3.39）。
3. P2 的标准差随深度上升（0.08 → 1.03 → 0.80），ReLU 保持稳定（0.19 → 0.48 → 0.36），深网上 ReLU 不仅更准也更稳。

### Fast 早降采样结构（`--arch fast`）

| 配置 | 精度 | MPC 元素 | 深度 | 6 层预算 |
|---|---|---|---|---|
| fast + ReLU + RGB + BN | **85.09 ± 0.23%** | 20,736 | 10 | 超出，hybrid |
| fast + ReLU + RGB + BN（RTX 4090，2026-10-23） | 84.51 ± 0.43% | 20,736 | 10 | 超出，hybrid |
| fast + P2 + RGB + BN | 79.07–79.69%（两次单种子，100 epoch, lr 5e-4） | 20,736 | 10 | 超出，hybrid-only 对照 |

对比：

- 4 卷积 VGG（64 通道）：88.55 ± 0.36%，164,096 个 MPC 元素；
- fast（32→64 通道，前两层 stride 2）：85.09 ± 0.23%，20,736 个 MPC 元素；
- 精度只低 3.46 个点，MPC 元素少 **7.9 倍**；按 12.9 ms/元素，桌面约 4.5 分钟/次，树莓派约 9–13 分钟。
- fast P2 在 lr 1e-3/50 epoch 下不稳定（57–60%），改用 lr 5e-4/100 epoch 后两次单种子为 79.69% 和 79.07%；同架构 ReLU 85.09，差 **5.40–6.02**；若同用 50 epoch，P2 是 77.24，差 7.85。P2 训练有偶发 loss 尖峰，稳定性明显不如 ReLU。
- fast P2 深度也是 10，不能 HE-only 部署；可部署的零交互基线仍是 2 卷积 P2 78.57%，hybrid fast 比它高 **6.52**。
- 2026-10-23 RTX 4090 独立复跑使用 3 个种子、50 epoch、batch 256，得到 84.51 ± 0.43%；per-seed JSON 位于 `results/raw_results/E1/cifar10/deep/gpu_20261023/`。它比 2026-10-20 的 85.09% 低 0.58 个点，单独记录，不与旧结果合并。

## OT 联网延迟基线（localhost, 2026-10-20）

命令：`secure_relu_net.py --net-self-test`（k=44, k_compare=14, f=8, sigma=30）。

| 指标 | 单元素 | 一层 1328 元素（外推） |
|---|---|---|
| 基础 1-of-2 OT 次数 | 27 | 35,856 |
| 耗时（localhost，CPU） | 21.7–26.5 ms（均值 24.4） | ≈ 32.4 s |
| 网络字节（双向合计） | 3,996 B（client 1866 发 + 2130 收） | ≈ 5.3 MB |
| 顺序往返（按 1.5 RTT/OT） | ≈ 40.5 | ≈ 53,784 |
| RTT=50ms 时延 | ≈ 2.0 s | ≈ 44.8 min |

结论：

- 精简电路已把单元素 OT 从 58 降到 27，实测与设计一致。
- 当前瓶颈是“逐元素串行”：一层 1328 个元素把 27 次 OT 重复 1328 遍，RTT=50ms 时要约 45 分钟/层。
- 下一步：元素并行批处理（去掉 1328 因子），再并行前缀/常量轮 DReLU（去掉 k 因子），最后 IKNP/离线预处理（降单次成本）。

### 批量 ReLU 实测（`--batch-relu-test`）

| n | 客户端耗时 | 服务端耗时 | 基础 OT | 消息数 | 字节 | max_abs_err |
|---|---|---|---|---|---|---|
| 2 | 35.1 ms | 35.3 ms | 54 | 82 | 8.3 KB | 8.44e-4 |
| 8 | 108.3 ms | 108.8 ms | 216 | 82 | 32.3 KB | 3.50e-3 |
| 128 | 1.65 s | 1.66 s | 3,456 | 82 | 512 KB | 3.38e-3 |
| 1328 | 17.1 s | 17.2 s | 35,856 | 82 | 5.3 MB | 3.75e-3 |

关键结论：

- 消息数与元素数无关：n=2 和 n=1328 都是 82 条；逐元素版本一层是 27×4×1328 = 143,424 条，批量版少约 **1,749 倍**。
- 一层 1328 元素：CPU 32.4 s → 17.1 s（约 1.9×）；RTT=50ms 时 44.8 min → 约 19 s（约 140×）。
- 字节数不变（约 5.3 MB/层），批处理降的是消息/往返，不是流量。
- 当前剩余瓶颈是 CPU：35,856 次椭圆曲线 OT；下一步用 IKNP/OT 扩展或 C 库把单次成本降下来。

## E5 · 逐层激活敏感度（posthoc, fast, seed73）

baseline（全 ReLU）：**85.16%**（CPU，50 epoch）。

| 替换层 | 替换后精度 | ΔAcc |
|---|---|---|
| conv1 | 66.66% | −18.50 |
| conv2 | 64.04% | −21.12 |
| conv3 | 54.27% | −30.89 |
| conv4 | 64.21% | −20.95 |
| fc1 | 51.37% | −33.79 |

结论：

- 训练用 ReLU、推理只把一层换成 P2，会掉 18–34 个点；BN 的 running stats 和下游权重都是按 ReLU 分布学的，不能事后替换。
- 这是“调度必须在训练时确定”的直接证据，也解释了为什么 §4.4 的“事后替换崩塌”实验会那么严重。
- planner 的 ΔAcc 需要 `measure_sensitivity.py --mode retrain`（每层单独用 P2 从零训练）；posthoc 只作为 collapse 证据，不能直接填进 planner。

### E5 retrain（单层 P2 从零训练）

baseline 84.45%（seed73，50 epoch，CPU）。

| 层 | 单层 P2 精度 | ΔAcc |
|---|---|---|
| conv1 | 84.44% | −0.01 |
| conv2 | 84.35% | −0.10 |
| conv3 | 84.91% | +0.46 |
| conv4 | 85.10% | +0.65 |
| fc1 | 85.05% | +0.60 |

结论：

- 单层 P2 几乎不掉点（−0.10 ~ +0.65），模型能吸收一层 P2；全 P2 的 79.1% 是**多层累积效应**，不是单层近似误差。
- planner 不能把单层 ΔAcc 线性相加；改用按 P2 层数的组合罚项 `0.0025·k(k−1)`：k=1 → 0，k=5 → 5%，与实测全 P2 的 −6% 基本吻合。
- 这给 planner 一个重要的调度自由度：1–2 层用 P2 几乎免费，可以用来省 MPC 元素/网往返。

### E5 planner（组合罚项，fast，预测）

`planner.py --arch fast --acc-min 0.82 --rtt-ms 50 --strategy constrained`：

| 精度 | MPC 元素 | hybrid 层 | RTT | 桌面时间@50ms | 调度 |
|---|---|---|---|---|---|
| 82.09% | 4,096 | 1 | 41 | 54.9s | conv1/conv2/conv4/fc1=P2, conv3=ReLU |
| 83.59% | 4,352 | 2 | 82 | 60.2s | conv1/conv2/conv4=P2, conv3/fc1=ReLU |
| 84.59% | 8,448 | 3 | 123 | 115.1s | conv1/conv2=P2, conv3/conv4/fc1=ReLU |
| 85.09% | 12,544 | 4 | 164 | 170.0s | conv1=P2, 其余 ReLU |

注：85.09% 的“全 ReLU”是 20,736 元素；把 conv1 单独换成 P2 不损失精度（E5 retrain），所以 12,544 元素就能达到同样精度。上表是组合罚项模型的预测，需用 `measure_sensitivity.py --mode schedule --activations ...` 实测验证。

实测验证（`p2,p2,relu,p2,p2`，seed73，50 epoch）：

- 预测 **82.09%**，实际 **82.87%**，差 +0.78（模型偏保守）；
- 4,096 个 MPC 元素、1 个 hybrid 层、RTT=50ms 时约 55 秒（桌面）；
- 相对全 ReLU（20,736 元素、5 个 hybrid 层、约 278 秒），MPC 元素少 **80.2%**、时间少约 **80%**，精度只低 **2.22** 个点。
- 结论：组合罚项模型可用，planner 在 82% 约束下选出的调度真实成立。
