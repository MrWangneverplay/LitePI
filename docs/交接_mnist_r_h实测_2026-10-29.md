## 2. 测量条件（写论文时必须标注）

- 拓扑：本机 WSL loopback + `tc qdisc netem`，纯时延（`bws 0`，不做 `rate` 整形），rtts = 1/5/20/50/100 ms，每点 1 次预热丢弃 + 4 次采样，`tcp_slow_start_after_idle = 0`。
- loopback 上 netem 对收发双向都生效，配置 D ms 实际加 2D ms RTT；拟合时已用 `delay_mult = 2.0` 除回（`analysis/netem_e2e.py::delay_mult`）。**若直接引用 run.json 里的 wall 斜率，必须同样除以 2。**
- 运行时：`mpc_runtime = litepi_sci`（SCI 路径），不是论文要求的 CrypTFlow2 远端部署；论文实现表需注明。

## 4. 口径警告（右侧入文档时请保留）

1. **不要用 wall 斜率单值当 r_h。** 只有 5 点时才有 4.28，若只取 RTT 1/5/20 三点会得到 15.8 的错误值——那次 rtt=20 的会话 wall 比 rtt=1/5 高出约 1.4 s，而 MPC 只涨 383 ms，属 CPU 抖动；同理 rtt=50 的 wall 反而低于 rtt=20（非单调）。
2. `_archived_mismatch/netem_slowstart_20261029/` 里是上一轮 **带 `rate 100mbit` 整形** 的数据（r_h 11.107）。整形队列在高 RTT 下饱和失真（rtt=50 与 100 的 wall 持平），**不得使用**。
3. `tcp_slow_start_after_idle` 本来就是 0，慢启动不是本轮差异的原因；差异来源是 rate 整形的队列效应。
4. 结论表述建议：在 SCI 运行时下，每 hybrid 层端到端 6.0 轮，远高于协议设计目标 r_h=1；该差距来自 SCI OT 内部往返，而非 ①/② 交换。
