## 1. M2 掩码域（P0）—— 已修复

**问题**：旧规则是"观测范围 +5%"，A_k ≈ B_k，每个元素的统计距离约 1/2。E10a 测到的单查询相关 0.37–0.42、符号命中 58–59%，都来自这里。

**新规则（v2）**：
- 掩码在 `[-A_k, A_k)` 上均匀采样，取值落在 2^-8 网格上；A_k = 2^σ_k · B_k。
- B_k 取不小于 1.25·max|z_k| 的最小 2 的幂（训练集统计）。
- σ_k = min(40, 42 − log2 B_k)。
- 每元素统计距离 ≤ 2^-(σ_k+1)。

**上限 2^42 的依据**：`analysis/check_mask_domain.py` 在 SEAL 上实测（结果见 `results/checks/mask_precision.json`）。
- 2^44 以内，份额误差 2 LSB，等于 CKKS 噪声底；
- 2^46 时为 7 LSB，2^48 时为 29 LSB，原因是 double 只有 53 位尾数。
- SCI 环不构成限制：份额按 mod 2^44 约简。

**改动文件**：
- `params_pi.py`：新增 MASK_SIGMA_TARGET / MASK_MAX_BITS / MASK_MIN_SIGMA / MASK_BOUND_MARGIN，写明推导。
- `mask_session.py`：
  - `MaskDomain.for_bound / from_observed`；整数网格采样，每元素用 16 字节 PRG 输出；
  - `covers()` 只承认 v2 域；
  - `mask_security_report()`（统计距离与 Q_max）；
  - `rule="v1"` 用于复现旧窄域，只作对照。
- `export_mask_domains.py`：直接导出 v2，文件附带 `security` 报告。
- `pi_server.py`：
  - STAT 里记录每层的 `mask_domains`（规则、log2 A、σ）；
  - `fit_mask_domain()`：密文剩余模数放不下满宽掩码时收窄，并记入 `mask_domains_fitted`。例如档位 B 在 s=00 下输出只有 61 位，σ 降到 26。σ<20 时直接报错。
- `leak_quant.py`（E10a）：分三组：复用 / 新鲜+旧窄域 v1 / 新鲜+协议 v2；新增单查询相关和符号命中率指标。
- `check_mask_session.py`、`check_output_modes.py`：测试跟着新语义更新。

**必须写进论文的结论**：
- 统计距离随查询次数累加。MNIST s11 每次查询是 2^-30，所以 Q_max(总距离 ≤ 2^-20) = 1024 次。
- 这是 CKKS 用 double 解码的固有上限，不是实现问题。
- §6.2 的多查询安全声明要改成"统计距离 + Q_max"的写法，用 `mask_session.py --report <file> --queries Q` 出数。

## 2. 字节压缩（P1）—— 已实现，逐项可开关

线格式由服务器在 SPEC 里宣布，客户端照用（`pi_proto.WireProfile`）。可选档位：

| 档位 | 内容 |
|---|---|
| baseline | 与旧数据逐字节一致 |
| zstd | SEAL 序列化压缩 |
| seeded | 客户端用 sk 对称加密，种子化序列化（M1、②、密钥减半） |
| modswitch | 服务器发 ①/M3 前丢弃接收方用不到的素数 |
| shortchain | 客户端按后续段需要的最低链层级加密（协议 §4.2 性质 2） |
| compact | 以上全部 |

**实现要点**：
- modswitch 和短链按 SEAL 实际素数**精确模拟 scale 漂移**（本参数下 21 位素数只有 1.20M–1.79M，s=00 到输出时 scale 是 2^29.2，不是 2^21），按密文实际 scale 定位数。
- 短链按输出档位分别给出层级，因为档位 B 要给输出掩码留空间。
- 短链和调度混淆（dummy-round）不能同时开：密文大小会泄露调度，服务器会拒绝这种组合。

**E4 结果**（`analysis/measure_wire_bytes.py` → `results/raw_results/E4/all/wire_bytes/seed73.json`）：
- baseline 与 E1 实测逐字节一致（MNIST s11 上行 2,752,909 B）；
- compact：在线通信降到 1/3.8（s=00）至 1/5.9（s=11），S_key 从 176 MiB 降到 45.5 MiB。

**正确性**：`analysis/check_wire_canonical.py` 用规范网络几何走真实服务器/客户端代码，覆盖 4 种调度 × 6 种档位，以及档位 B，全部通过。

**接入**：`pi_server.py --wire`、`pi_client.py --loopback --wire`、`eval_hybrid_accuracy.py --wire`（非 baseline 时结果目录自动加 `_wire<名字>` 后缀）。E1 精度脚本已改为调用 `pi_client` 的同一套收发循环（`send_input / ciphertext_loop`），两份客户端代码不会再分叉。

## 3. E5 planner（P1）—— 成本常数已换成实测

`analysis/cost_model.py` 从结果文件拟合成本常数，每项都带 provenance：
- **客户端加解密**：来自 E1 SEAL 记录，3840 个样本。
- **SCI MPC**：`9.66 ms × K_h + 0.0037 ms × 元素数`（旧常数是每元素 12.9 ms，差约 3400 倍）。
- **服务器**：E1 forward_s。
- **字节**：E4 wire_bytes。
- **r_h**：读 `results/rounds/r_h_*.json` 及其口径。
- **Pi5**：MPC 按 E2 加解密时间比例（4.0×）从桌面换算，标注为 scaled-from-desktop，**需要在 Pi5 上补 hybrid 实测**。

`planner.py` 接入 `--cost-model / --objective client|server|e2e / --bandwidth-mbps`，并新增 `random_schedules()`。
`gen_e5_data.py` 重写：实验方案的 6 种策略（含随机 ×5 平均）、六维指标（E_client 记 null）、四维 Pareto、planner 自身开销，外加 `measure_list`（前沿上每个调度的实测命令）。

**新结果要点**：
- 三个浅网上 Adaptive 都选 s=00，与 E1 结论一致。
- VGG 上 Adaptive（00100）支配 rule/greedy（11001）。
- 随机 ×5 中，VGG 有 0/5 被 Adaptive 支配（随机抽到的调度精度更高、成本也更高），**H5 的"支配"要限定在同一精度约束下表述**。
- fast/VGG 的精度和服务器成本是模型值（JSON 的 `basis` 里已注明）。

## 4. E7 消融（P2）—— 两项已实现

`analysis/gen_e7_ablations.py`：w/o planner（固定 HE-only）、w/o client-aware（目标改为服务器时间）；扫描设备 × RTT。

**结论（诚实）**：按现有实测数据，rebound = 1.0，客户端成本没有反弹。原因是服务器成本模型只随 K_h 线性增长，两个目标选出的是同一个调度。
- 打平规则已修正：服务器目标不再用 MPC 元素数打平。
- 要让这项消融出效果，需要逐层、逐层级的服务器开销实测（hybrid 会重置层级，后续线性层更便宜，服务器可能反而偏好更多 hybrid）。

## 5. E3/E9（P1）—— r_h 参数化，加 netem 端到端

- `rtt_sensitivity.py`、`gen_e9_data.py`：R = 2 + K_h·r_h，r_h 从文件读取，可用 `--r-h` 覆盖（如 7 = CrypTFlow2 的 log ℓ+2）。输出 JSON 记录 r_h 的值、口径和来源。
- `analysis/netem_e2e.py`：客户端出口加 netem，跑真实查询，覆盖 E3 网格和 E9 丢包 × 抖动网格。抖动用均匀分布，与 E9 模型的方差公式一致。

**关于 r_h，务必看**：
- `results/rounds/r_h_sci_*.json` 的 1.0 只统计了 Python 主通道（文件里的 caveat 自己也写了），SCI 内部轮次没算进去。
- `netem_e2e.py --mode e3` 跑完多个 RTT 后，用"时延对 RTT 的斜率"反推真实总轮数。netem 同样会延迟 SCI 自己的 socket，所以这个结果**包含 SCI 内部轮次**。
- 结果写入 `results/rounds/r_h_netem_<ds>.json`，scope = end-to-end，`cost_model.load_r_h` 会优先使用它。
- 回归方法已用合成数据验证，每层 7 轮能准确还原（7.00）。

## 7. 深网密文（P1）—— conv2/conv3 可行性已跑通

- `analysis/deep_hybrid.py`：hybrid 层之后，客户端和服务器各自对自己的份额做多通道 im2col，客户端逐块加密；服务器加上自己的份额后，用新的 C++ 原语 `matmul_rows` 计算。
  - 该原语用对角线法，先乘后转：在 2^21 尺度上旋转会带来 0.06–0.3 的误差，在 Δ² 尺度上可以忽略。整个卷积只消耗一个层级。
- `analysis/check_deep_hybrid.py`：fast 网 conv2/conv3，客户端份额为 ±2^35 量级，误差 3×10⁻³。
  - 每层上传 5/9 个密文：baseline 4.4/7.9 MiB，compact 1.0/1.9 MiB；
  - 服务器 8/14 s（单线程，未做 BSGS）。
- **范围**：只支持"前面是 hybrid 的卷积"。P₂ → conv 需要在密文上重排（GAZELLE 式旋转），未实现。所以深网调度要上密文，第一层之后的每个卷积前都必须是 hybrid。
- **需要**：用真实权重重跑（`--weights datas/weights/fast_relu_*.npz`），再把 pool+fc 接上，跑完整前向。
